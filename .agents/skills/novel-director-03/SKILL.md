# 03｜资产检查与新增

02导演台本确认后调用，资产审定后进入04走戏。输入为已确认台本或单测给定的角色／地点、场次、动作和状态。03按场次定位资产，05初排镜序时建立稳定镜号，06沿这些镜号设计几何故事板并完成正式渲染；改剪由05同步，不在06另编号。

按[分镜设计职责与交接](../novel-director-06/references/分镜设计职责与交接.md)，03负责身份、体型、造型／状态、用户采用画风、物体固有色和材质依据。02选场级光影美学，04落实现场位置、持握、照明光区及其变化；06决定实际画框、景深和逐镜光影表现。资产展示光和角色卡摆姿不能覆盖分镜决定，也不要求03制作每镜表演变体。场景母本用于地貌、材质和既定环境关系，其默认曝光、灰雾与调色不自动成为所有分镜的美学方案；用户明确锁定的画法或颜色继续保留，区分原件中哪些特征属于确认范围，不因修灯光擅自换风格。

## 资产需求不确定，先问用户

先读用户要求、项目说明、相关台本及已有确认，并实际查看候选原件。仍有不确定的资产需求，**必须先问用户想要什么，收到回答后再设计制作受影响的资产**。适用于新建、变体、改造及复用是否合适的判断，不能靠“符合剧情”“通常这样穿”或模型默认外观替用户作主，也不能先画完再让用户纠错。

按正在制作的资产类型询问本次未定内容：

| 资产类型 | 询问方向 |
|---|---|
| 人物母本 | 年龄感、体态、身型比例、脸型五官、外形气质、基准发型。只定这个人长什么样，不问职业装、日常穿搭或本场妆容。 |
| 剧情造型／状态变体 | 以已定母本和当前剧情为依据，问服装风格、整套搭配、颜色材质、配饰鞋履、本场妆容及发型整理、受伤或脏湿等状态需求。脸和身型已定就不重新选人。 |
| 场景、道具、声线 | 场景问时代地域、空间风格、档次、陈设与材质；道具问样式；声线问语言、口音与声音气质。 |

已明确的内容直接沿用，不把表格做成每次必填问卷。画风确认不等于资产方案确认，母本确认也不等于本场服装确认。

问题写清哪项未定及已有依据，直接询问需求；必要时给少量具体方向。母本例如：“年龄已定，身型、长相和发型你希望是什么感觉？”变体例如：“人物母本已定，这场赴宴的服装和妆容你希望什么风格？”只暂停受影响资产及其依赖制作，其他已明确的工作可继续；等待期间不采用猜测方案，不把沉默当确认。一般的连续推进授权不能替代尚未明确的资产需求。

## 先打开库里的候选原件

按[主 Agent 的目录约定](../../../AGENTS.md)确定当前项目根，从输入取得最低限度的需求，先查该项目 `资产库/资产索引.md`，依次找同剧角色、可跨剧选用的演员外观、该角色衣橱和已有状态。跨项目候选仅来自用户指定或明确可共用的库，不自动扫描其他作品。按名称、别称和辨识点打开实际原件，同时确认可用范围与版本。索引不存在或无记录时，按同一范围查当前项目已有的角色包或用户指定的库，确认确实无合适原件才判缺。待清理旧项目不作默认来源。

**先认人，再核对本场出演状态。** 先对体态与身形比例、脸型与五官辨识点、基准发型及发际轮廓，再对当场身份、生活处境、生理状态、穿着与经历造成的变化。演员外观 ID 管稳定外形，本剧角色 ID 管身份与声线，造型／状态 ID 挂回同一角色和母本。认得出是同一个人、当前状态也符合剧情，才可直接复用。

| 查库结果 | 本步动作 | 还要读什么 |
|---|---|---|
| 核心外形、本场造型和状态都符合 | 直接引用已审 ID 和原件，登记本场使用；完整角色建档或补齐资产时，同时核对主声线及用户确认依据，缺失或未确认则按下节处理。 | 已有角色资料足够时，不重读剧本或索要新参考；完成本次范围内的角色与声线引用后交付。 |
| 人物符合，本场要换工作装、私服或其他搭配 | 从衣橱选符合本场已确认要求的整套。确实缺这套，需求明确后基于同一人补妆造变体；未定搭配先询问。 | 查对应场次与上次离场，分清剧情规定和仍待用户决定的妆造。 |
| 人物符合，本场生活处境、生理状态或外观发生变化 | 先查已有状态并查看原图。缺适配版本时，按明确的范围、程度及起止设计可见变化；程度或表现需求不确定先询问。 | 必要时只核对状态形成、延续到本场及本场观众可知的片段。 |
| 本剧还未选角，库里有核心外形相符且可跨剧复用的演员 | 交候选原件与匹配点给用户选角，确认后绑定本剧角色 ID；本场服装另按剧情变体设计或从已审衣橱取用。 | 已给的角色要求足够就用它选。不可把上一部剧的人物经历、服装和伤损带入。 |
| 没有合适的核心外形，或候选与剧本长期身份确有实质冲突、无法据现有设定裁定 | 先锁定缺的是哪项稳定特征，再进入下节研读与新设计。已定角色遇到有剧情依据的年龄阶段或长期外形变化，保留角色 ID，按需补阶段版本。 | 此时才扩展阅读，不因一件衣服或一道伤重新选人。 |

**人物母本只定体态、身型、长相和基准发型。** 女性统一穿简洁瑜伽衣，男性统一穿背心、短裤，采用低干扰的纯色展示服以看清身体比例；不设计剧情服装、配饰或本场妆容，也不因穿运动类展示服就把所有人画成健身体型。展示服不登记为角色默认穿搭。

剧情服装、妆容与出演状态归同一角色的造型／状态变体；服装沿已确认的本场需求与连续性，连续从上一场跑到街上就沿用离场那套。旧母本如带剧情服装，仅按已有确认核对身份，服装另按剧情造型引用；更新母本时沿上述规范，保留旧版本与有效引用。

## 让变体符合本场出演状态

**母本负责认回角色，变体负责当前剧情的服装、妆造与状态。** 先按本场身份、场合、戏内时间和已确认需求设计整套服装，再叠加本场状态；已有适配衣橱直接复用。换装保持已定脸型、身型和基准发型辨识，本场整理或剧情变化另按依据处理。母本展示服不自动带入变体；明确的剧情状态优先于母本的基础气色与神情。

1. **把状态落成可见变化。** 从本场身份、经历和状态的程度，选择真正受影响的肤色与唇色、神情、体态、发式、衣着或护理痕迹。贫困可通过有依据的服装用料、穿用年限、修补与搭配呈现，清洁程度另按剧情判断；受伤落实部位、程度及当场反应；死亡状态落实相应的失去生气的气色、神情与身体状态，伤痕、腐败程度或其他异常另取剧情依据。只呈现当前时刻已成立、且允许观众看到的特征。
2. **明确参考图各自管什么。** 实附身份母本用于体态、身型、脸与基准发型，服装参考及已审剧情变体用于本场穿着和妆造，状态原件用于伤损等变化，风格图决定画法。首次建档也将母本与剧情变体分开；不能用一张穿剧情服装的图同时充当两者。
3. **把采用设计写进实际生图提示词。** 写清“同一角色出演［本场身份与状态］；继承［母本体态、身型、长相与发型辨识］；穿着［已定剧情服装、颜色材质与搭配］；本场妆造及状态为［具体可见表现与程度］；沿用［连续性］；画法遵循［风格附件］”。不能仅靠“工作装版／贫困版／受伤版”等名称，也不能让生成模型照抄母本的瑜伽衣或背心短裤。

在现有角色卡或状态记录中简记“剧情依据｜继承特征｜本场可见变化｜适用场次”，并入本步一次自检：实际查看成图，分别判断是否仍是同一角色、关键状态是否看得出来。母本的健康红润或精致状态覆盖了剧情变化，即为状态未落实；标签、提示词和冷色打光不能替代实际成图证据。记录具体偏差及采用状态，交付使用符合本场状态的原件。

## 只有核心外形待定时，才扩展研读和定型

处理第一章的新角色，也可向后读约 **10–20 章**。从中段开始时兼顾首次出场、最近状态和后续重要戏份。先按姓名、别称和角色关系定位，再实际读影响设计的场景，判断长期身份、年龄阶段、叙事份量、反复出现的任务和角色如何变化。按证据回看库中候选，仍无合适者才新增演员外观。章节不足就注明实际范围，把影响永久定型的缺口集中提出。

在现有角色设计卡中分清母本与剧情变体：母本写实际章节与两三条依据、角色定位、体态身型、脸型五官、基准发型及稳定辨识特征；变体写适用场次、服装轮廓与搭配、颜色材质、妆造和状态。只把当前剧情允许观众知道的标志画入当场版本，未来揭晓的身份、伤损和服装不能提前出镜。

## 美术风格由用户定

先查库。纯复用且符合本剧已定画风、资产需求及确认范围的原件直接引用。新画资产或跨剧借用画法时，按以下两条路径确定本剧风格；画风明确后，人物妆造、场景等需求仍按本步前述规则处理。

- **用户给了风格参考图**　按指定原图制作，记录路径和适用范围，实际生图时附图。同一剧已确认且仍适用的依据直接沿用，多图用途不清或互相冲突时集中问一次。
- **没有适用的风格图或已确认画风**　先用简短文字给用户可选方向，说明线条、色彩和明暗处理的区别，等用户明确选定再画。如果用户已明确指定文字画风，可按它制作一张本就需要的代表性母本送审。用户认可这张的画法后，记录为本剧的风格样张，后续直接引用。

在本章引用表表头登记本剧的风格依据（用户原图，或用户确认的方向及样张）。画风与定脸、服装、场景参考分别标明用途。用户要求照某人或某件实物设计时，缺对应参考就报缺等待。已定身份的变体沿用母本的辨识特征，当前状态按上述规则改绘；未经确认的网图或模型自生图不能替代用户参考。

新建或修改视觉资产统一用 Codex 原生 `imagegen` 的内置 `image_gen`，有用户参考图时必须实附原图。纯文字定风格的首张用已确认描述，后续实附认可的风格样张。新人物先以标准展示服制作身份母本，分开呈现完整头像与身体比例；形象完成后按下节选配主声线，连同设计卡和样音提审，确认后制作需要的剧情变体。变体实附母本与适用的服装、造型／状态原图，标明各自用途。交[06第二轮原生单张](../novel-director-06/SKILL.md#第二轮原生imagegen绘制单张分镜)及第三轮BANANA重渲染时，母本只供身份与身型，剧情变体供当场服装、妆造、状态、固有色和材质，风格样张供画法；展示服、展示光和摆姿均不替代本场决定。第一轮只提取体型与必要辨识依据，不把高细节展示图混入几何故事板参考。

### 角色卡的生图构图与背景要求

角色卡将**独立头像**与**不生成头部的身体展示**分开排版。两区都必须完整放在各自画框内部，并留出清楚的背景空隙；不能用画框边缘遮住不想显示的部分。

- **身体区直接生成无头部的体态与穿着展示。** 母本用前述标准展示服看清身型，剧情变体展示已定的本场服装。只生成领口、双肩以下至双脚的身体、服装和手脚；不生成头、脸、头发，也不生成向画框外延伸的脖子。领口、双肩、双手、衣摆及双脚都完整入画；领肩上方与双脚下方留出可见背景，人物不能顶边或出框，不表现血腥断颈或切口。
- **头像区完整生成头部。** 发顶、两侧头发、耳部、下巴与所展示的肩部都放在画内；发顶上方和左右留白，不切发顶、不顶边。母本头像体现已定长相与基准发型，变体头像体现同一角色的当场妆造；两区的身份、穿着与状态一致。
- **由生图模型一次完成上述构图。** 提示词必须明确“身体区不生成头部”“身体的领口和肩部上方留白”“头像发顶完整且上方留白”。不得使用“头在画外”“颈部延伸出画框”“画框从颈部裁切”等会引导顶边截断的写法。不得先生成带头全身图，再用代码、图像处理工具或其他后处理裁掉头部。
- **所有展示区使用简单背景。** 使用纯色或极轻微渐变的干净底色，不放房间、街景、家具、灯具、道具陈设或其他叙事环境。身份母本兼作风格样张时也遵守。
- 展示光让母本的五官和身体比例、变体的服装材质与本场状态清楚可读；简单背景保留明暗分离和立体塑形。此要求适用于角色卡，不限制正式分镜的剧情场景。
- 交付前随本步一次自检确认母本只承担身份定型、变体落实本场妆造；身体区没有头且领肩完整留白，头像完整且发顶留白，双手、衣摆、双脚均未出框，背景简单。只据实际成图记录，不把提示词写对等同于画面已符合，不另起循环审核。

## 主声线由03推荐，用户听样确认后绑定

先查当前项目资产库及角色卡。已有用户确认的角色声线，就直接复用项目内样音，不重新查公共库、选配或询问；跨章节、换服装或临时状态均沿用。已确认但仍引用公共库的旧声线，按原版本补复制入项目库并更新引用，无须重新确认。只有绑定记录而无确认依据的声线仍须提审。首次选配时查看角色母本与设计卡，结合年龄感、体态、面相、性格、身份、语言口音和说话习惯，确定音色、音区、语速、气息与表演方向；外形与声音的反差取角色或剧情依据，需求未定先问。

首次选配或更换主声线时，查[公共声线库说明](../../../公共资源/声线库/使用说明.md)与[声线索引](../../../公共资源/声线库/声线索引.json)，筛选并试听实际样音，推荐一条最匹配的候选。向用户交付角色名、可直接播放的样音和一句匹配说明，明确询问是否采用，并等待回答；不能只交声线ID、文件路径或音色描述。多个角色可一次集中提审，各角色的样音和选择必须对应清楚。无法实际试听时如实注明，仍须提供可播放样音供用户判断；来源标签、试听状态及语言冲突、短样音、许可备注如实保留。

确认前在现有角色卡及引用表中记“候选，待用户确认”，不正式绑定、不作为下游已定声线。用户明确采用后，将实际样音原样复制到当前项目资产库中该角色包的 `声线/`，按样音ID与版本命名、保留原格式，并核对复制件与源文件一致。同版本已存在就复用，不按章节重复复制；公共库后续更新不覆盖项目已采用版本。角色卡绑定项目内样音，登记确认依据及日期并标“用户已审”；只保存公共库链接不算完成入库。形象已审、公共库已试听或一般的“继续／自主完成”授权均不替代这次声线确认。用户否定后按反馈调整候选；确无适配样本或指定声线不可用时集中报缺，不擅换、不自动生成新声线或整章配音。只建公共库时不绑定项目角色。

角色卡“声线配置”沿用现有字段：`voice_id`及版本、`sample_id`及版本、项目内样音相对路径、公共库来源与原样音版本、匹配理由、语言口音、音色、语速、气息、表演方向、试听状态、采用状态、确认依据与日期；项目资产索引登记该角色声线，本章引用表引用同一项目样音及确认状态。公共库用于选配和来源追溯，后续制作只读取项目内已确认的绑定与样音，不依赖公共库在线或路径仍可用。对白、OS、呼吸和笑声沿用同一声音身份，情绪样音挂回原声线，换角保留旧章节版本。

提审示例（实际交付须在文字下嵌入对应的可播放样音）：“周医生：推荐这条略低、带颗粒感的男声，适合他沉稳直接的说话方式。请听样音，是否采用为周医生的主声线？”

## 场景、区域与关键道具

先查库并实际看图，按已确认的时代地域、空间风格、档次、陈设、材质和剧情用途判断能否复用。名称相同或通路可用不足以确认设计符合需求；未明确的设计方向先问用户。新场景在需求明确后设计空间格局、出入口、固定陈设与材质特征，服务01基调及02拍法；04再落实本场调度与照明。

已有场景的日夜、陈设状态和道具磨损优先复用或补变体；新区域沿用已定方位与出入口，给出影响走戏的相对空间与接触点。只新增本章确实要用的原件，关键道具的外形、材质及状态同样依据明确需求制作。

按 02 的 `H` 编号核对已采用高阶设计所需的资产条件，例如纵深、高差、通路、镜面或透明介质；只检查方案实际依赖的项，优先复用。把已有条件与需补的设计写进本章资产引用表。既有场地无法支持特殊效果时，带具体冲突交 02 调整方案或交 04 安排现场。

## 入库与停止点

只把用户确认的原件登记为可复用资产。新原件进入项目资产库，项目内现有原件只链接；公共库选定并获确认的声线按上节复制入库。保留已完成章节引用的版本与路径。本步交 `03_章节资产引用表.md` 与 `03_资产交付.json`，已有指定引用表就沿用。表头登记本剧风格依据，正文记录“场次／动作｜剧内角色或地点｜已定外观、造型／状态或区域 ID｜本场关键可见特征｜原件版本与路径｜入场承接”。每场角色引用明确区分身份母本与当场造型／状态原件；母本完成不等于剧情服装已定，缺本场变体就如实登记待定。只写已定资产和场次、状态入场信息，不猜实际出镜或章末状态；缺项集中列入提审说明。

**交付页面按角色集中展示身份母本、本次使用的全部变装／状态图和可直接播放的主声线。** 变装标明适用场次，图片可放大并打开原件；沿用项照实显示已有审定状态，不混入未采用的旧方案。使用[共用阅读器的03资产交付接口与示例](../../../前端/导演阅读器/数据接口.md#03角色资产交付)，章节只维护JSON与原件，不另建HTML，不等待05数据。只以服装／道具出现的人物不列作出演角色。场景与道具继续在引用表提审。

页面与引用表使用同一批有效原件和确认依据，修改时同步。按主Agent要求做一次数据校验，并实际打开页面确认图片完整适配、声线可播放；交付页面链接，请用户最后确认本次整套角色资产。已有母本、造型和声线确认保留，不重新选配；整套确认单独记在JSON的review，未答复为pending，用户明确采用后才记approved及确认依据，并同步引用表。若要求修改，只处理反馈涉及的项，更新页面后交回确认，不重审其他已定资产。

交付示例：“[第三集角色资产交付](http://127.0.0.1:4318/assets?chapter=掌中之物%2F章节%2F第三集)：三位角色的母本、六套本集造型和三条声线已齐，请最后确认。”实际交付替换为本次作品、数量和有效链接。

形象与主声线已审、样音已入项目库且引用有效、交付页获最终确认后，03才标完成并交04；准备齐全但尚未确认时标“待最终确认”。等待期间可继续不依赖待定项的工作。单测只交指定原件，不要求补齐整套页面。08从引用表读取角色身份、当场造型与声线；09读取本表、交付页及已有确认生成`章节交接.md`，不回写资产库。
