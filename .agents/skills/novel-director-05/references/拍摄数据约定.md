# 05–07 共用的拍摄数据

`05_拍摄设计.json`是逐步补全的共用容器，不是05必须生产的字段全集。05新增段落采用的剪辑方法与节奏，以及落实该方案的镜序、时码、切点与声画承接；06新增景别、机位、构图、代表时刻和图像；07新增运镜执行。上游内容以原件引用为准，不为填满容器另写一版。文稿只展示自然语言采用决定。

所有新生产同时遵守[共用阅读器数据接口](../../../../前端/导演阅读器/数据接口.md)，字段形状参照[可运行示例](../../../../前端/导演阅读器/示例/05_拍摄设计.json)。页面直接读取当前 JSON，程序集中在 `前端/导演阅读器/`。交付时运行一次共用校验，并查看本次代表镜头。

专业设计沿[分镜设计职责与交接](../../novel-director-06/references/分镜设计职责与交接.md)确定唯一负责步骤。该表用于工作方法，不另建章节检查数据。06第一层的清晰对象、清晰范围和代表时刻随已有画框文字交接，第二层必须执行；07动态焦点和08声画写作沿同一决定，不靠图像模糊程度猜测采用意图。

## 数据归属与版本

06由[主Agent](../../../../AGENTS.md#调度与交付边界)派出的独立执行者串行维护。先读取整段`edit_plan`、`shot_order`及各镜`edit.description`，连同完整上游原件，按[镜头设计执行指令](../../novel-director-06/references/从剪辑方案到镜头设计.md)成组设计后写入已有画框字段；不新增切口分析表、候选表或子智能体过程字段。分页和第二层渲染继续使用同一套采用设计。

新制作采用 `schema_version: 4`，顶层为 `data_revision`、`design_revision`、`design_status`、`design`；07 执行后增加 `motion_design`。

- `data_revision` 随有效数据变化；`design_revision` 随已采用的拍法、现场状态、图幅或时序变化。运镜提示词记录所依据的 `source_design_revision`。
- `design_status`：working 表示设计中；review_ready 表示 05 设计与 06 图像已一致、可审；approved 记录本次实际审定或自主定稿授权的依据。05 单步完成的文字初排仍为 working，其本步结论写 `review.plan`。
- `design`可逐步包含`project`、`beats`、`shot_groups`、`shot_order`、`scenes`、`board_sheets`、`lighting_setups`、`look_setups`、`effect_setups`、`shots`、`review`。这是可用集合，不要求05建齐，更不要求为空集合补造内容。除设置、顺序和摘要外，各集合以稳定ID引用。
- 未执行的图像或提示词部分保持缺省。旧编号按实际职责识别，有效图像与时码继续沿用；退役工程和实现记录归入临时目录。

| 写入者 | 维护部分 |

## 走戏、镜组与生图上下文

02每段采用拍法决定观看组织，03提供资产，04场地图与连续走戏提供现场依据。05据此选定剪辑方法与节奏，再落实镜序、声画切点与镜长，不删改上游已确认要呈现的内容。06直接读取01—04原件、05段落方案及镜表完成画面设计，07读取这些来源及正式图设计执行。下面是各步可用的共用字段，不是05的待填表。

| 位置 | 内容与用法 |
|---|---|
| `scenes[场号]` | 04场地图`plan_ref`和走戏`source_ref`、固定地标、稳定对象ID与03原件引用；全部实际关系轴／视线轴／运动轴及光源、状态通过原件定位，不重抄轴表。04不供摄影主轴或观看侧；06依据这些现场关系自行采用摄影方向及衔接，不另建场地尺寸、坐标或位置。 |
| `shot_groups[组号].continuity` | 兼容已有上游状态摘要，05不重新生产；新制作通过`source_ref`读04连续走戏。 |
| `shots[镜号].story_moment` | 对应动作时刻；回忆、并行线、省略等需要区分时，说明剧情时序与剪辑顺序的关系。 |
| `board_sheets[页号]` | `image_ref`为第一层采用的几何故事板，`group_refs`和`frame_ids`关联所含画框；`generation`记录故事板提示词及实附的04场地图、相邻采用画格与各自用途。高细节角色、风格和场景美术原图留第二层，不混入组页参考。 |
| `design_frames[].sheet_ref / panel_id / panel_region` | 每个摄影镜头以唯一代表图关联原页的一宫，`panel_region` 供阅读器定位实际画框；代表时刻属于本镜，显示区间覆盖本镜。格位来自实际原图，不据模板假定。 |
| `design_frames[].board_art / board_art_resolution_px / board_art_generation` | 第二层Gemini Nano Banana 2.1正式图的章节相对路径、实测`[宽,高]`及采用的重绘输入。06先用原生imagegen准确落实构图、镜头、景别、机位、透视及动作接触，裁图检查通过后，实附有效原生图与必要资产给Gemini完成真人棚拍质感和更鲜明的光影塑形。`board_art`指向实际完成并采用的最终图，尺寸记实测值；07／08只取此正式单张。旧图保留真实来源，不伪改生成工具。 |

第一层先设计整段连续镜头，再分页生成几何故事板。一宫对应一个镜号，按剪辑顺序排列；只用无五官人体块、场地骨架和必要道具轮廓表达景别、机位、透视、位置、遮挡与关键动作。跨页顺序生成，后次实附前页采用画格，局部特写之后补最近能说明同场关系的画格，同时继承同一04阶段。姿态、事件与实际关系取自04／05对应时刻，摄影主轴、观看侧和方向承接沿06采用决定，不能把04全部轴同时当禁越边界；分页不重置现场。每镜实际画框遵守中景居中等构图禁令，不靠改变景别名称、轻微偏移或斜拍绕过。

第一层的`generation.tool`如实记录原生imagegen，`prompt`记录准确画框指令和几何画法；景深在`composition.frame_description`或现有`note`中交采用决定，组页不精画模糊、服装、材质或常规光影，必要隐藏关系只用明暗块占位。第二层的`board_art_generation.tool`记录实际使用的`gemini-nano-banana-2.1`；`prompt`既锁定第一层镜头、清晰与显露要求，也写清真人棚拍质感及本镜光影塑形，`references`实附有效原生单镜图、03原件及必要同场正式图。参考用途分别为镜头几何、身份状态、表现衔接，不能让Gemini重选景别、机位、透视或摆人。04照明与05显露时序指导表现，相邻正式图不替换本镜画框或焦点状态。参考项记`image_ref`和`purpose`，裁图记正式来源页及`panel_region`，不依赖临时副本。两层沿用现有字段，原生图是镜头设计依据，`board_art`是Gemini最终采用结果；无实际成图不伪填工具回执或完成状态。

逐镜裁图后、任何正式单镜渲染前，06必须按[裁图检查规则](../../novel-director-06/SKILL.md)实际看本镜草稿、上一剪辑镜及必要的同一行动线前镜，对照04现场、05切点和代表时刻，一次检查裁切、数量与人体结构、比例透视、支撑接触、构图及跨镜空间和动作。未检查、结构有错或跨镜关系无法成立的草稿均不放行；不能以原页已采用或用户已授权代替实际观察。修正后的几何画格须成为正式故事板的有效来源，同步`image_ref`、实际格位和受影响引用，再从该来源取得本次渲染参考；不保留“临时草稿已修、正式原页仍错”的两套有效图。变化仅在图像执行时按原设计修正，不偷偷改现场、镜序或时间。

检查与定向修复验收只在已有`review.board`的`scope / findings`或原页`observation`简记，注明受检镜号、有效来源页／宫和比较镜号及结论，不新增检查表或放行字段。草稿通过后，未生成的正式图仍省略`board_art`，逐幅生成状态仍为`required_not_generated`；不得把草稿通过写成正式图`adopted`。按[06图像审核优先级](../../novel-director-06/SKILL.md#图像审核优先级)，未解决P1／P2在现有观察中记`needs_revision`，缺少必要依据记`blocked`；P3先放行，仅在现有备注一次列可选调整，P4直接通过且不列问题。正式单张已生成且仅有P3／P4时，可填`board_art`并将逐幅观察记为`adopted`，不等于用户已审，不因此跨越委托停点。此结论只对实际看过的有效图与比较来源成立，修图或相关现场／时序变化后，定向验收受影响关系再使用，不能沿用旧结论。

以下仅为写法示例，不代表已验证任何章节；示例用于解释如何依据实际影响分级，不限定检查范围，也不为同类问题预定级别：“S102｜P04/P02草稿：已修正多出的手和肩臂连接；对照S101及04门口阶段，人物仍在原门柱旁，画面间隔缩短来自侧向取景，未发生额外走近。定向验收通过，可生成正式单张。”未通过时写具体阻断，例如“S102仍把未移动的人画到门口，草稿待修，不生成正式单张”；不附逐项打勾清单。正式图的非主视觉杯子颜色不同但不影响剧情和动作，可写“已采用；杯色差异为可选调整，不阻断后续”；眼区特写略露鼻尖且无畸形、无叙事影响，不按裁边违约拒收；难察觉且无影响的背景锁扣无需记问题。

## 坐标与时间

- `project` 记录画幅、`resolution_px`、`pixel_aspect`、`fps: {num, den}`、全局 `frame_range` 与预算。单镜、声音和工具规格沿用[主 Agent](../../../../AGENTS.md)。
- 全局帧从 1 起，首末帧均计入；时码左闭右开。硬切后镜首帧为前镜末帧加一；叠化记录实际重叠。镜长来自选定入出点，声音以实际持续帧段计时。
- 02／04 已定的行为、话语与反应映射到同一时间线，同时发生的动作锚点与声音区间保留重叠。动作和话语可跨镜延续；总长按剪辑时码计算，重叠内容只计一次。
- 场地空间沿用04图中的方位、地标、相对位置和轴线，不要求米制原点、长度、角度或相机参数。SVG区域、图像裁切和标注坐标只是文件显示数据，不代表现场测量；有依据的旧字段保持兼容，不为填满字段补造数值。
- 05写事件与信息范围；06选代表时刻和景别，用相对位置、裁切、层次与大小关系表达构图；07用可见关系描述起落幅和运动。画内`bbox`或点位为可选显示辅助。时码、帧段、画幅、图像尺寸等必要交接数据照常维护。

| `intent / composition` | `intent`兼容旧数据，不要求05另写。06第一层以`scale_in`记代表景别，`frame_description`自然叙述实际画幅内的裁切、主体区域、大小、留白、透视、遮挡、接触及清晰范围，例如“人物与手同时清楚，门洞可辨，门内人影不可辨”。不新增一套景深字段；第二层及07读取该决定。起落幅由07细化。 |
| `camera` | 05阶段省略未定部分。06第一层以`placement`自然语言引用04阶段及所用关系，写定06采用的摄影主轴／观看侧、代表帧的相对机位、视高、拍向及必要方向转换。普通镜简写沿用，变化处写明承接；不另建机位或轴线分析表，不默认附数值参数。07读取这些决定，运动执行写入`motion_design`。 |
| `axis_ref / axis_events` | 有既存数据时，`axis_ref`定位04真实关系，06在已有事件记录或`camera.placement`写定摄影转换及其承接；04的关系变化不自动等于摄影换轴。07按06采用方案执行换侧。没有独立轴线数据时直接通过04图及阶段定位，不为接口重造轴表。 |
| `blocking / anchors` | 兼容已有动作数据，不要求05重写。动作、持物、接触和身体状态以04为准；05仅在切点与承接中引用相应事件，06／07直接读取04并保持画外进度。 |
| `lighting_ref / look_ref / effects` | 02给场级光影美学、色彩空气关系及已采用特殊机制；04给实现它的现场光源、控光、反射补光、光区与变化；03给确认画风、固有色与材质，不把资产展示光或灰雾曝光固定成分镜。06第二层按本镜视点与画框定亮暗体块、塑形、背景衬托、颜色及空气表现，写入已有setup或实际渲染输入。改变整场美学交02，改变现场照明条件交04；07承接动态。景深决定以`composition.frame_description`为准，不在多个setup另写不同焦点。07／08不能以动态效果改掉已定清晰或显露关系。 |
| `sound_cues` | 05只记录已有声音的时间映射与跨切延续；声音内容和听觉设计直接读02／04引用，持续声用同ID跨切。 |
| `edit` | 05的核心交付。`description`自然叙述具体切入／切出的既有动作或声点、接向谁或什么、跨切承接；必要重叠补`overlap_frames`。原有分项字段兼容，不要求另列切镜理由。 |
| `design_frames` | 由06创建，每个摄影镜头仅含一项：图号、代表时刻、整镜显示帧段及实际画面设计，再补来源页、格位与正式图。05阶段省略，不填假图号或暂定代表帧来满足校验。06制作中允许分镜尚未齐备；提交共同审定时摄影镜头与代表图一一对应。`design_ref`可引用原页，正式图使用`board_art`。 |
| `design_frames[].annotations` | 06 按净图落动作／视线箭头。07 定好运动后在同一列表串行补 `camera` 箭头或固定 `note`，标 `author_step: "07"`，保留 06 的标注。箭头是 `motion_design.shots[镜号]` 决定的显示层。单纯补显示标注更新 `data_revision`，已审画框、时码或采用的剪辑改变才更新 `design_revision`。 |

组页与单张分别保存两层采用输入。第一层观察视点、轴线、视线、画幅、景别、透视、遮挡、接触、跨宫连续及禁用构图，检查清晰决定可执行，不以精细度判采用。第二层`observation`对照同一画框与文字，判断景深、资产、表演，以及实际明暗塑形、颜色和空气层次是否呈现采用的美学；有光向、有纹理、没有结构错误不等于画面美感成立。该判断并入已有首张正式样张与本步一次检查，不新增评分或独立审美表。仅完成组页时仍列正式图待完成。改变核心拍法交02，现场／表演交04，剪辑交05，代表画面或清晰决定由06先同步采用文字及受影响画格，再更新正式图与07。生成偏差依06优先级处理：P1／P2按有效设计直接修，P3先放行交用户决定，P4完全通过；不变更设计来迎合重大错图，也不把符合P3／P4的差异列为阻断；级别依实际影响决定，不能由对象名称或示例匹配得出。

同场通用光影段落只交接共同来源与已定美学；`board_art_generation.prompt`还须写出该镜采用的亮暗主次、形体与背景衬托、色彩及必要空气关系。只复制“冷灰漫射光、重光影、固有色克制保留”不能算逐镜设计。受光与取景关系确实相同可沿用，不能为差异每镜换灯或调色；相机或人物转向后按同一现场重新推导。没有独立setup时直接在现有提示词交采用决定，不为接口补一套灯光字段。

`review.plan`只简记05一次剪辑自检的实际范围与实质问题，`review.board`记录06实际图像观察。05核对方法是否真正成立、是否服务02拍法，以及`edit_plan`所定各区间秒数、镜数、组织顺序和变速是否由镜表实现；不能仅以时码合法或普通镜未超3秒判通过。修改镜数、镜长或切点时同步段落方案与文稿，不保留两种节奏决定。镜数、总时长、最长镜长和超限数按数据计算；有依据的长镜头和高阶镜头不计普通镜头超限。完整分镜交付与摄影镜头一一对应。06比较实际尺度、方向与注意承接；不要求相似景别为零，不因静帧成立而宣称运动已验证。检查记录不附进正文。

高阶H编号和02来源在`duration_basis.reason`登记，不再要求每镜`intent`重复引用。按已有镜序与时码核对每分钟2–3处，静态与动态合计，同一效果只计一处；效果时刻确需精确交接时登记一次，不另生产逐层论证表。06／07沿同一编号观察图像与执行结果。长镜数量和高阶设计点数量分别统计。

## 07 运镜提示词数据

`motion_design` 包含 `source_design_revision`、`status`、`shots` 和 `review`。每镜保存 `frame_id`、一句 `intent` 与完整 `prompt`。镜长、正式图路径和代表时刻通过镜号、图号读取同一份 `design`。字段与示例见[阅读器接口](../../../../前端/导演阅读器/数据接口.md)。

提示词表达起幅、动作与相机的先后、移动或留驻的过程、节奏变化、经过正式分镜的时刻和落幅承接。声音只作为已有声点的触发。已确认长镜头和高阶镜头由07承接既定方案细化执行并校准用时，可超过3秒；05在`duration_basis`区分登记。核心方案变化交02，画框或时码变化分别交06、05。段落或总长变化同步04／01及下游08，并按新时间线核对高阶设计次数。

`review` 记录本次纸面与图像推演的实际范围、结论和待办。`status` 为 working、review_ready 或 approved，采用依据按实际确认记录填写。修改提示词或标注递增 `data_revision`；改变 05／06 的有效设计递增 `design_revision`，旧提示词由版本关系标明待同步。

07 同源导出 `07_运镜提示词.md` 供复制与交接；阅读器按镜号展示 JSON 中的提示词。08以04段落读取本数据及台本、资产引用、正式图与运镜稿，结合实际画框补全、强化表演及同框活动，写成连续声画，交付`08_分段声画提示词.md`；不回写设计字段或再维护一份JSON。09引用已有设计、声画稿与核对结论。
