# Gemini Nano Banana 2.1｜正式单镜重绘

本技能是[06第二层](../novel-director-06/SKILL.md#第二层gemini-真人质感与光影塑形)的执行工具，不另设计镜头或改变步骤编号。由同一个06执行者调用，不递归委派。用户只要求修改方法时不发起生图。

## 输入与分工

- 先实际查看有效原生单镜图。构图、镜头视点、景别、机位、透视、人体与接触、跨镜关系须已经按06检查通过；P1／P2几何错误先回原生imagegen修正，不能让Gemini顺带重新设计；P3／P4依06规则放行，不因无影响微差重复修草稿。
- 参考图1锁定完整镜头几何和代表时刻；必要03资产按顺序另附，只负责角色身份、当场造型／状态、固有色和材质；同场正式图仅衔接表现。逐张写清参考职责和冲突优先级，不能仅把路径写进提示词。
- 默认重绘为真实演员在搭建实景内拍摄的电影画面，保留正常毛孔、细纹、发丝、织物与实物反射。按06本镜采用决定做专业棚拍控光、鲜明的亮暗体块、形体转折和背景衬托，保留暗部细节与关键叙事信息；不把场地改成背景纸或加入摄制设备，不用蜡皮、3D游戏感、统一滤镜代替真人质感。
- 画幅与原生图及项目一致，默认请求2K，用户明确规格优先。比例和2K／4K是API档位，保存后记录真实宽高和编码，不虚报尺寸、不为凑比例裁掉采用画框。默认最终JPEG；明确需要PNG时脚本在内存转换，不保存中间JPEG。
- 完整镜头、清晰范围、表演与本镜布光要求读取06及上游原件，不用“同上”或一段通用“重光影”替代。用户另有明确风格／模型要求时先按授权范围处理，不能静默换服务。

## 调用

使用本目录维护的 `scripts/generate.py`（Python 3.10+）。该客户端沿用已经实际用于本项目的标准库调用实现；固定模型 `gemini-nano-banana-2.1`，Google官方端点 `https://generativelanguage.googleapis.com/v1beta/interactions`，请求 `store: false`，输出仅读取最终 `model_output` 图片。

密钥只读取 `GEMINI_API_KEY`：优先当前进程，Windows未继承时读取当前用户持久环境。禁止在代码、请求、日志或聊天中保存／显示密钥。参考图以真实文件字节或内存Base64传入，最多14张，优先最少有效组合。

在工作区根目录运行，构建请求后经标准输入传入，不创建请求JSON、提示词草稿或日志文件。下列路径与正文须替换为本次实际材料：

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$request = @{
  prompt = @'
在此写入06已采用的完整单镜重绘要求：原生图锁定镜头几何，真人棚拍质感，本镜具体的明暗塑形、清晰范围和当场状态。
'@
  aspect_ratio = '16:9'
  image_size = '2K'
  output = (Join-Path (Get-Location) '项目/作品/章节/章节名/06_正式分镜/S001.jpg')
  references = @(
    @{path='<本轮检查已通过的原生单镜图绝对路径>'; instruction='参考图1：严格锁定构图、镜头视点、景别、机位、透视、人数、位置、动作及接触。'}
    @{path='<角色当场状态原件绝对路径>'; instruction='参考图2：仅恢复角色身份、服装和状态，不替换参考图1的构图或姿势。'}
  )
}
$request | ConvertTo-Json -Depth 8 -Compress |
  python -B '.agents/skills/nano-banana-2-1/scripts/generate.py'
```

也可用 `image_base64`、`mime_type`、`instruction`传入已在内存中的参考图，不打印Base64。API图片输出请求固定 `response_format.mime_type: image/jpeg`；输入支持PNG、JPEG、WebP，不等于API输出可任意换编码。JPEG保存只需标准库，PNG转换需使用已安装Pillow的Python。

用户明确指定代理时，`--check`及实际调用都传入同一个 `--proxy`；仅影响本进程，失败不回退直连。不改系统代理或自动寻找其他服务。

`--dry-run`仅校验JSON标准输入，不联网、不生成、不写文件；`--check`只检查密钥和模型端点。两者均不能报为图片已经生成。修改方法或脚本时优先做无网络验证，不消耗生图额度。

## 成图、错误与交付

- 每个请求只生成一张独立图。镜头设计已经确定、文件互不依赖时可按可用并发独立提交，不能重复发出同一在途请求。
- 默认禁止覆盖。更新本轮最终图需已有明确授权才设 `overwrite: true`；委托范围内按06优先级处理P1／P2属于已有修复授权，无须再问，P3须用户选定调整后才修；不覆盖输入原件，不保留多轮备份或失败样张。采用的原生设计图与Gemini最终图是必要交付；裁图副本按06由正式原页／区域重建，不作为新的正式过程文件保存。
- HTTP400明确参数校验错误时查官方文档修正已确定的问题，保持模型和任务，校验后最多重试两次；修改客户端须同步本技能。鉴权、地区、额度、模型不可用或限流时报告真实原因，不循环、不静默换模型。网络中断或超时可能发生在服务端已处理后，不自动重发；只有用户明确要求重试时再提交该请求。
- 成功回执须有实际文件、编码和尺寸。将真实模型、采用提示词与参考用途写入现有 `board_art_generation`，将真实尺寸写入 `board_art_resolution_px`；请求响应、缓存、过程日志均不落盘。不要将计划值或模型可访问当成生成证据。
- 按[06图像审核优先级](../novel-director-06/SKILL.md#图像审核优先级)合并查看正式图一次。分级是处理原则，不是问题类型清单，未列举的情况同样按本镜实际影响判断；达到P1／P2的错误直接定向处理，无须另问；默认最多额外生成一次，用户明确扩大的修复范围按授权执行，修后只确认本次问题及受影响接切，仍有P1／P2则据实列待修。P3影响有限的可选调整先放行，一次交用户决定；P4无影响微差完全通过，不为P3／P4自行消耗重画次数。不能把任何偏离原生图都判成待修，也不倒改正确设计或循环全章审核。网络中断、超时等请求重发仍按上条处理。
- 正式制作将最终采用图写入 `board_art`，供07／08引用；用户只要求独立风格试片时单独交付，不擅自替换有效引用。展示实际最终图并说明真实尺寸，不把“自主采用”写成“用户已审”。

接口格式依据：[官方生图文档](https://ai.google.dev/gemini-api/docs/image-generation)、[Interactions API](https://ai.google.dev/api/interactions-api)。出现实际接口错误才按官方资料定位，不凭猜测更换模型名。
