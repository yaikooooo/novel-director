# 导演阅读器数据约定

本文件、contract.mjs 和[示例JSON](示例/05_拍摄设计.json)共同定义当前唯一的阅读接口。示例与真实章节由同一套 public/app.js 渲染。

## 制作和阅读

1. 在 项目/作品/章节/章节名/ 维护 05_拍摄设计.json、阶段文稿与素材原件。
2. 05按[拍摄数据约定中的最小示例](../../.agents/skills/novel-director-05/references/拍摄数据约定.md#05实际需要生产的数据)建立剪辑数据。可运行示例含后续分镜字段，只供对应步骤参考，不要求05复制填满；已有其他步骤成果继续保留。
3. 打开根目录“启动分镜档案.cmd”。示例入口为 http://127.0.0.1:4318/example，上方“作品与章节”切换真实章节。
4. 更新数据后点“刷新数据”，读取当前章节原件。章节目录无需生成HTML。
5. 交付前执行一次下面的命令，集中处理输出问题，再在阅读器查看本次新增或更改的代表镜头。

    node 前端/导演阅读器/check.mjs "项目/作品/章节/章节名"

正式程序位于 前端/导演阅读器/。示例目录属于软件模板，作品数据存放在 项目/。

## 唯一数据来源与版本

05_拍摄设计.json 的 schema_version 为4。顶层保留 data_revision、design_revision、design_status、design；07 执行后增加 motion_design。

- 有效数据改变时递增 data_revision。
- 已采用的设计改变时递增 design_revision。
- design_status 使用 working、review_ready 或 approved，依据实际审定记录填写。
- 阅读器保留完整设计对象，正文展示主要字段，折叠区提供完整记录。生成提示词和参考原件在“状态”中读取。
- motion_design 记录 07 的运镜提示词及其依据版本。页面只读当前共用 JSON 和对应原件。

## 05 必须提供的结构

| 路径 | 格式与用途 |
|---|---|
| design.project.title / chapter | 作品与章节名称。 |
| project.fps | 例如 {"num":24,"den":1}。实际帧率为分子除分母。 |
| project.frame_range | [首帧,末帧]，全局帧从1开始，首末均计入。 |
| project.resolution_px / aspect_ratio | 已有画幅与规格沿用，例如[1920,1080]与16:9；不是05新增设计，纯剪辑数据可缺省。 |
| design.shot_order | 当前剪辑顺序中的稳定镜号。 |
| design.shot_groups | 以组号为键，提供shot_ids、对应04段落的source_ref及edit_plan。edit_plan是一段自然语言采用决定，写具体剪辑方法、组织次序、各节奏区间秒数与镜数及变速位置；与05文稿段首同源，不另写体验目标、上游策略或状态摘要。 |
| design.scenes | 以场号为键，只引用04场地原稿source_ref及已有场地图plan_ref，不重写场地内容。 |
| design.shots | 以镜号为键，登记以下每镜内容。 |
| design.sound_timeline | 按需提供已有声音的source_ref和全局时段，供跨切引用；原词与声场读02／04，不要求05重抄。 |
| design.review.plan | 一次自检的简短范围和实质问题，不要求逐镜论证或审核矩阵。 |

05先在段落edit_plan选定方法与节奏，逐镜只提供kind、group_ref、scene_ref、frame_range和edit.description。edit.description与自然语言剪辑稿同源，写具体切点和声画承接；采用重叠时才补overlap_frames，声音需精确映射时才补sound_cues。镜表须实现段落方案的次序与密度，改剪时一同更新；结构校验只查数据合法性，不能证明剪辑方法和节奏成立。旧稿缺edit_plan仍兼容读取，不视为已完成新05要求。05不生产intent、blocking、anchors、composition、camera或design_frames，已有数据保持兼容，不删除他步成果。06开始设计时写composition.scale_in、camera.placement和composition.frame_description，并创建design_frames。scale_in记录代表景别，起落幅由07在既定方案内细化。

kind使用camera或black。各段按全局帧连续排列，普通单镜最多3秒。上游已确认的长镜头和高阶镜头可超过3秒，在duration_basis分别登记type为long_take或advanced_camera，reason引用既定方案和采用用时；高阶保留H编号。普通段省略，黑场仍最多3秒。07校准后由05同步实际时序，镜长只取frame_range；重叠用edit.overlap_frames显式登记。

每分钟2–3处按[02选型与计数标准](../../.agents/skills/novel-director-02/references/高阶设计选型.md)人工判断，采用的静态与动态设计合计，同一 H 编号只计一次。结构校验不代替特殊效果的创作判断。

05阶段design_frames缺省，校验和阅读器接受纯剪辑数据，不要求暂定代表帧。06开始设计时创建每镜唯一的design_frames项，display_frame_range覆盖整镜，representative_frame由06选择并位于镜内。制作中可有尚未设计的镜头；design_status为review_ready或approved时每个摄影镜头必须有代表图记录。07已声明交付范围内的镜头也必须有实际对应记录。阅读器可临时显示剪辑卡片，但不把它写成分镜数据。改变切点或镜长由05同步，代表时刻由06维护。

黑场用 kind=black，按帧段显示纯黑，design_frames 可为空。

## 06 正式分镜、原页与格位

06由独立子智能体执行，先完整读取05段落`edit_plan`、镜序与切点及上游原件，按[镜头设计执行指令](../../.agents/skills/novel-director-06/references/从剪辑方案到镜头设计.md)成组设计，再写入以下字段并分页出图。采用结果仍使用现有结构，不为设计推演或子智能体执行另加字段；共用JSON串行维护。

光影来源按02场级美学、04现场照明与控光条件、03确认画风及固有色逐级读取。06将本镜具体亮暗体块、主体与背景衬托、颜色和空气表现写入已有board_art_generation.prompt，必要共用关系沿用lighting_setups/look_setups；通用光源说明不代替逐镜决定，不增加灯光参数表。实际样张与第二层observation同时判断采用美学是否呈现，不能仅凭光向、纹理、可读性或数据校验宣称好看；结构校验不评判视觉美感。

06分两层沿用同一套字段、镜号与代表时刻：第一层读取04全部实际关系轴、视线轴、运动轴及阶段变化，自行选择摄影主轴、观看侧和方向承接，连同相对机位写入camera.placement；04不预选摄影方向，也不能把全部轴同时当禁越边界。06用原生imagegen把构图、镜头视点、景别、机位和透视准确画出来，几何故事板只画人体块、场地骨架和必要道具，景深通过composition.frame_description或现有note交接。逐镜实际检查通过后，第二层实附有效原生图与必要资产给Gemini Nano Banana 2.1，完成真人棚拍质感、更鲜明的光影塑形及既定清晰关系。Gemini不能改动原生图的镜头几何、人数、动作或接触。第一层不附高细节风格和资产图。两层提示词和实际工具分别存于board_sheets[].generation和design_frames[].board_art_generation，不新增逐层或轴线分析表。实际画面遵守06构图禁令，专业责任见[共用约定](../../.agents/skills/novel-director-06/references/分镜设计职责与交接.md)。

| 字段 | 格式与用途 |
|---|---|
| board_sheets[页号].image_ref | 相对章节目录的第一层几何故事板原页路径。 |
| width_px / height_px | 原页实际宽高。 |
| group_refs / frame_ids | 原页所含镜组和图号，须与每幅的引用一致。 |
| status / observation / generation | 页级镜头关系观察、采用的故事板提示词及实际参考；04图提供对应阶段的现场与全部实际轴线，同场采用的几何画格衔接状态及已定方向；摄影主轴、观看侧与画框由06选择。 |
| design_frames[].id | 稳定图号，示例为 S001-F01。 |
| sheet_ref / panel_id | 原页ID及格位ID。 |
| panel_region | [x,y,width,height]，以原图左上为原点的实际像素。 |
| design_frames[].board_art | 06第二层Gemini真人质感／光影重绘的最终采用净图，使用章节相对路径。原生画格约束构图、镜头、景别、机位、透视、人物数量、位置与动作时刻，07／08引用此最终单张。原生图完成不等于正式图完成。05初排和旧版手稿可省略，历史已采用图沿用真实原件，不追改工具来源。 |
| board_art_resolution_px | 最终采用图的实测 `[宽,高]`，与 project.resolution_px 的时间线规格分别记录。 |
| board_art_generation | 第二层实际采用的tool、prompt和references。新流程tool记录gemini-nano-banana-2.1；prompt锁定第一层构图、镜头、景别、透视、清晰与代表状态，并写明真人棚拍质感和本镜具体光影塑形。references中原生单镜图锁几何，03原件定身份状态，同场图仅衔接表现，记image_ref和purpose。裁图引用正式来源原页及panel_region，不依赖临时副本。工具字段是实际来源，不以计划代替调用事实。 |
| raw_panel_region | 可选，原页格框。采用视口须位于此框内部。 |
| status / observation | 实际生成状态和逐幅观察。 |
| annotations | 阅读器叠加的箭头与说明，具体结构见下节。 |

“分镜图册”按原页panel_region显示第一层原生镜头设计图；原页模式允许点击画格进入对应镜头。“正式分镜”读取board_art查看第二层Gemini真人质感与光影结果。两者保持同一画幅、视点、景别、主体位置、透视和事件状态，分别用于镜头设计与正式结果查看。只有故事板时可交付第一层测试，不标为正式单张已完成。阅读器的既有SVG功能示例仍如实记录reader_demo_svg，不因方法更新伪称为模型成图。

下列仅演示新流程的生成记录写法，不是既有示例图片的生成证明；生产时替换为实际输入与回执，沿用现有字段，无需升级schema_version：

```json
{
  "board_art_generation": {
    "tool": "gemini-nano-banana-2.1",
    "prompt": "严格保持参考图1已确认的取景、视点、景别、透视与抓袖接触，重绘为真人棚拍质感；侧光照出手背和袖褶的转折，近侧躯干保留深暗，以较暗门框衬出动作，保持两人和门同时可辨。",
    "references": [
      {"image_ref": "06_正式分镜/P01.png", "panel_region": [0, 0, 960, 540], "purpose": "参考图1：原生imagegen采用画格，裁出并检查后真实附入，锁定镜头几何与动作接触。"}
    ]
  }
}
```

正式单张生成前，06须实际检查裁好的本镜草稿及前后承接，具体范围按[06裁图检查规则](../../.agents/skills/novel-director-06/SKILL.md)。跨镜真实距离依据04地标与位置关系、05经过时间及已有动作判断，不能只比较两图中的大小和像素间隔。结构或关系错误先修几何草稿并同步采用原页、格位与引用，定向验收通过后才实附修正版渲染；旧错误草稿不得继续作为有效参考。

本次草稿检查及修复验收的范围、有效来源和结论，使用已有design.review.board的scope/findings或原页observation简记，不增加字段。原页adopted不能代替裁图检查；草稿放行不能代替正式图完成或用户审定。尚未生成正式单张时board_art仍缺省、生成状态仍为required_not_generated，不将逐幅observation标成正式图adopted。按[06图像审核优先级](../../.agents/skills/novel-director-06/SKILL.md#图像审核优先级)，未解决P1／P2记needs_revision，缺必要依据记blocked；P3先放行，现有备注一次列可选调整，P4直接通过且不列问题。正式图已生成且仅有P3／P4时，board_art引用该图，observation.status可记adopted，不冒称用户已审，也不跨越委托停点。不新增优先级字段。分级是实际影响的判断，不是问题类型枚举；未列举的情况照样适用，不根据关键词或示例自动决定状态。这些记录不允许绕过实际看图，结构校验也不能验证画面正确。

observation.status 是该幅采用判断，优先于生成状态 status。采用状态不直接推导用户审定。

| 状态 | 页面行为 |
|---|---|
| adopted | 标记为采用；包含已放行的P3／P4，P3可保留一次可选调整备注，不计入待修。 |
| needs_revision | 未解决P1／P2，或用户明确要求修改的项目；显示具体观察，原图仍可阅读。不能仅凭差异类型或是否命中示例决定状态。 |
| generated | 已生成、待采用。 |
| required_not_generated | 显示画面需求和时码。 |
| blocked | 显示受阻和已有说明。 |

06设计后、组页未生成时，保留本步已定的图号、代表帧、显示时段和画面设计，省略sheet_ref与格位。05不创建这些字段。组页生成后补实际路径和格位；尚待单张重绘时board_art缺省，状态为required_not_generated。正式图状态依据实际结果填写，页级采用不等于单张完成。

## 箭头与短说明

位置以本镜画框归一化，左上为 [0,0]，右下为 [1,1]。在原页上对应 panel_region，在单张正式图上对应完整画幅；06 按最终单张定位，重绘保持与来源宫相同的构图关系。

    {
      "annotations": [
        {
          "kind": "action",
          "points": [[0.65,0.26],[0.44,0.26]],
          "label_at": [0.07,0.13],
          "label": "视线先转，手停在书页"
        },
        {
          "kind": "camera",
          "points": [[0.08,0.82],[0.27,0.82]],
          "label_at": [0.05,0.74],
          "label": "慢移向前，保留门与人物"
        }
      ]
    }

action 显示动作实线箭头，camera 显示机位虚线箭头，note 只显示短说明。points 可用多个点描述弯折路径，label_at 定位说明文字。原页和逐镜共用这组标注。06 阶段只填 action 及相关 note。07 将采用的 camera 箭头或固定 note 补进同一 annotations 列表，填写 author_step="07"。箭头是独立显示层，原图沿用。

## 声音与机位

需要跨切计时时，在design.sound_timeline[声音ID]提供上游source_ref和frame_range；已有kind、source、text等字段继续兼容，但不要求05另写。说话人、原词、声源变化、听点和表演读取02／04原件，不由05重新设计。

每镜 sound_cues 通过 cue_ref 引用声音，active_frame_range 为本镜内有效区间，用 continues_from_previous 和 continues_to_next 表达跨切延续。

空间图用scenes[场号].plan_ref引用04场地图，生产时沿用已交付图；旧数据缺省仍可读取。若一张SVG含多个镜组，再写plan_size=[宽,高]和plan_regions，例如{"G01":[0,0,900,620]}。坐标使用SVG自身viewBox单位，仅用于页面定位，不是现场尺寸。页面据本镜组取对应区域；省略分区时显示完整图。

## 07 运镜提示词

`motion_design` 保存运镜设计，逐镜以稳定镜号关联正式图。镜长、代表时刻和净图路径读取 `design.shots[镜号]`，与 05／06 共用同一来源。

```json
{
  "motion_design": {
    "source_design_revision": 1,
    "status": "working",
    "shots": {
      "S001": {
        "frame_id": "S001-F01",
        "intent": "让门外脚步打断观众对室内的观察。",
        "prompt": "3秒。起幅用远景同时看见左侧房门与右侧桌边的人，右窗光照着书页。前段保持参考图的空间关系，约1.46秒仍处于正式图构图。约2.5秒门外传来脚步，摄影机才朝门的方向横移，把门在画面中的分量加重，桌边的人仍在右侧。刚建立向门的动势便切到人物中景，脚步延续。"
      }
    },
    "review": {
      "scope": "本轮已完成镜头的纸面与图像推演",
      "findings": []
    }
  }
}
```

- `status` 使用 working、review_ready、approved，确认依据另记实际授权或用户反馈。
- `source_design_revision` 对应当前 `design_revision`。05／06 设计变更后，提示词需同步；只改提示词递增 `data_revision`。
- `shots[镜号]` 包含 `frame_id`、一句 `intent` 和可直接复制的完整 `prompt`。每镜对应唯一正式图。黑场沿剪辑时码处理。
- 整章交付覆盖全部摄影镜头；局部委托增加 `shot_ids` 列出本次范围。working 可保留尚未写完的镜号，review_ready／approved 覆盖所声明范围。
- 提示词中说明参考图落在开头、途中还是结尾，时间位置与既有代表帧一致。起幅、触发、运动过程、落幅和跨切承接由 07 设计。
- `review` 集中记录本轮纸面与图像推演范围、结论和待办。阅读器的“运镜提示词”页可逐镜阅读和复制；“状态”保留已有检查。
- `07_运镜提示词.md`从同一JSON导出，标题列镜号、镜长、正式图链接与代表时刻，高阶点带H编号；正文只写一段自然语言采用的运镜执行。intent保留在数据中，不另列意图和说明栏。检查记录留在review，修改后JSON与文稿同步。

## 08 分段声画提示词

08按04连续段落与银幕时长，读取02台词／OS与表演、03角色声线、04动作情绪与声音、05时序及07运镜，实际查看06最终单张并对照上游，补全、强化具体表演及同框活动，写成连续声画，交付章节内的`08_分段声画提示词.md`。每段列时间与镜号范围，附图清单登记“镜号／@图片N／board_art 原件”。可复制正文以“不要背景音乐，不要字幕”和段长开头；第一镜与每次切镜处就近写“分镜参考 @图片N”，引用该镜的最终单张图后接具体表演与声画，写法见[08技能及完整示例](../../.agents/skills/novel-director-08/SKILL.md)。每镜单独提供图片附件，静态构图由图承载，一份提示词仍覆盖04的完整段落。

声线ID、样音版本和音色总述留在03及资产库，不进入08可复制正文；实际附样音后只写简短音频与角色映射。当句的语气、情绪及呼吸表演仍保留。平台交付默认只配置视频节点，图像、样音和完整声画直接进入该节点，不要求额外的展示素材或文字节点。

该文稿作为阶段文件在“章节文稿与原件”中读取，不新增 JSON 字段，不改变 `schema_version: 4`，不替代 `motion_design`。版本与范围来源记在文稿中；09 汇报按实际完成情况引用。
