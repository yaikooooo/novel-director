# 导演阅读器数据约定

本文件、contract.mjs、assets-contract.mjs 和[示例JSON](示例/05_拍摄设计.json)定义共用阅读接口。03资产与05之后的分镜分别由公共页面读取，章节不保存页面副本。

## 制作和阅读

1. 在 项目/作品/章节/章节名/ 按当前步骤维护03_资产交付.json、05_拍摄设计.json、阶段文稿与素材原件；03不提前建立05数据。
2. 05按[拍摄数据约定中的最小示例](../../.agents/skills/novel-director-05/references/拍摄数据约定.md#05实际需要生产的数据)建立剪辑数据。可运行示例含后续分镜字段，只供对应步骤参考，不要求05复制填满；已有其他步骤成果继续保留。
3. 打开根目录“启动分镜档案.cmd”。示例入口为 http://127.0.0.1:4318/example，上方“作品与章节”切换真实章节。
4. 更新数据后点“刷新数据”，读取当前章节原件。章节目录无需生成HTML。
5. 交付前执行一次下面的命令，集中处理输出问题，再在阅读器查看本次新增或更改的代表镜头。

    node 前端/导演阅读器/check.mjs "项目/作品/章节/章节名"

正式程序位于 前端/导演阅读器/。示例目录属于软件模板，作品数据存放在 项目/。

## 03角色资产交付

章节维护`03_资产交付.json`，入口为`/assets?chapter=作品%2F章节%2F章节名`，也可从阅读器顶部“03资产交付”进入。页面按角色展示身份母本、本次使用的全部变装／状态及可播放声线；图片完整适配卡片与放大窗口。仅作为服装或道具出现的对象留在引用表，不虚增出演角色。

`schema_version`固定为1；`title`、`chapter`为作品与章节，`reference_ref`指向本章资产引用表。`characters`按交付顺序排列，每人含`character_id`、`name`、`mother`、`variants`和`voice`。各项只存名称`label`、实际媒体路径、现有审定状态`status`及可选的确认依据`confirmation`；变体另有适用场次`scene`。图像用`image_ref`，项目内样音用`audio_ref`，均相对章节目录；无变装用空数组。资产版本沿原文件路径与引用表，不复制图片或另建声线库。

`review`仅记录本次整套交付的最终确认：准备齐全为`{"status":"pending"}`；用户明确采用后改为`{"status":"approved","confirmation":"实际日期及用户确认内容"}`，同步引用表。已有单项确认保留；修改影响组合的资产后，将本次整套状态退回pending。页面只读，用户在聊天确认，不由点击试听、页面浏览或校验通过自动采用。

下例为格式示意，路径须换成当前项目的有效原件：

```json
{
  "schema_version": 1,
  "title": "示例作品",
  "chapter": "第一集",
  "reference_ref": "03_章节资产引用表.md",
  "review": { "status": "pending" },
  "characters": [{
    "character_id": "CHAR-LIN",
    "name": "林岚",
    "mother": {
      "label": "标准身份母本 v1",
      "image_ref": "../../资产库/角色/林岚/身份母本_v1.png",
      "status": "已确认 · 本次复用"
    },
    "variants": [{
      "label": "浅灰西装",
      "scene": "诊室",
      "image_ref": "../../资产库/角色/林岚/诊室造型_v1.png",
      "status": "待最终确认"
    }],
    "voice": {
      "label": "成年女中音",
      "audio_ref": "../../资产库/角色/林岚/声线/主声线_v1.wav",
      "status": "已确认 · 本次复用",
      "confirmation": "沿角色卡已记录的用户确认"
    }
  }]
}
```

`check.mjs`会检查该文件的结构、重复角色、媒体类型和项目内原件路径；仅有03数据也可校验。它不判断用户是否认可。03随本步一次检查实际打开页面、放大图片并播放样音；04承接整套确认，08继续读引用表与项目声线，09引用此页和实际确认状态。

## 唯一数据来源与版本

05_拍摄设计.json 的 schema_version 为4。顶层保留 data_revision、design_revision、design_status、design；07 执行后增加 motion_design。

- 有效数据改变时递增 data_revision。
- 已采用的设计改变时递增 design_revision。
- design_status 使用 working、review_ready 或 approved，依据实际审定记录填写。
- 阅读器保留完整设计对象，正文展示主要字段，折叠区提供完整记录。生成提示词和参考原件在“状态”中读取。
- motion_design 记录 07 的运镜提示词及其依据版本。页面只读当前共用 JSON 和对应原件。

## 05 必须提供的结构

| 路径 | 格式与用途 |
|---|---|
| design.project.title / chapter | 作品与章节名称。 |
| project.fps | 例如 {"num":24,"den":1}。实际帧率为分子除分母。 |
| project.frame_range | [首帧,末帧]，全局帧从1开始，首末均计入。 |
| project.resolution_px / aspect_ratio | 已有画幅与规格沿用，例如[1920,1080]与16:9；不是05新增设计，纯剪辑数据可缺省。 |
| design.shot_order | 当前剪辑顺序中的稳定镜号。 |
| design.shot_groups | 以组号为键，提供shot_ids、对应04段落的source_ref及edit_plan。edit_plan是一段自然语言采用决定，写具体剪辑方法、组织次序、各节奏区间秒数与镜数及变速位置；与05文稿段首同源，不另写体验目标、上游策略或状态摘要。 |
| design.scenes | 以场号为键，只引用04场地原稿source_ref及已有场地图plan_ref，不重写场地内容。 |
| design.shots | 以镜号为键，登记以下每镜内容。 |
| design.sound_timeline | 按需提供已有声音的source_ref和全局时段，供跨切引用；原词与声场读02／04，不要求05重抄。 |
| design.review.plan | 一次自检的简短范围和实质问题，不要求逐镜论证或审核矩阵。 |

05先在段落edit_plan选定方法与节奏，逐镜只提供kind、group_ref、scene_ref、frame_range和edit.description。edit.description与自然语言剪辑稿同源，写具体切点和声画承接；采用重叠时才补overlap_frames，声音需精确映射时才补sound_cues。镜表须实现段落方案的次序与密度，改剪时一同更新；结构校验只查数据合法性，不能证明剪辑方法和节奏成立。旧稿缺edit_plan仍兼容读取，不视为已完成新05要求。05不生产intent、blocking、anchors、composition、camera或design_frames，已有数据保持兼容，不删除他步成果。06开始设计时写composition.scale_in、camera.placement和composition.frame_description，并创建design_frames。scale_in记录代表景别，起落幅由07在既定方案内细化。

kind使用camera或black。各段按全局帧连续排列，普通单镜最多3秒。上游已确认的长镜头和高阶镜头可超过3秒，在duration_basis分别登记type为long_take或advanced_camera，reason引用既定方案和采用用时；高阶保留H编号。普通段省略，黑场仍最多3秒。07校准后由05同步实际时序，镜长只取frame_range；重叠用edit.overlap_frames显式登记。

每分钟2–3处按[02选型与计数标准](../../.agents/skills/novel-director-02/references/高阶设计选型.md)人工判断，采用的静态与动态设计合计，同一 H 编号只计一次。结构校验不代替特殊效果的创作判断。

05阶段design_frames缺省，校验和阅读器接受纯剪辑数据，不要求暂定代表帧。06开始设计时创建每镜唯一的design_frames项，display_frame_range覆盖整镜，representative_frame由06选择并位于镜内。制作中可有尚未设计的镜头；design_status为review_ready或approved时每个摄影镜头必须有代表图记录。07已声明交付范围内的镜头也必须有实际对应记录。阅读器可临时显示剪辑卡片，但不把它写成分镜数据。改变切点或镜长由05同步，代表时刻由06维护。

黑场用 kind=black，按帧段显示纯黑，design_frames 可为空。

## 06 正式分镜、原页与格位

06由独立制作子智能体执行，读取05整段剪辑与完整上游原件，按[镜头设计方法](../../.agents/skills/novel-director-06/references/从剪辑方案到镜头设计.md)成组设计并写入以下字段；分镜文字及三轮图像依次交另一[独立检查者](../../.agents/skills/novel-director-06/references/独立检查与放行.md)对照上游判级，直接回报主Agent，对应关放行后才推进。共用JSON仍由制作方串行维护，检查者只读，主Agent不重复专业审核。既有design.review.board.scope/findings及observation简记检查者、阶段、受检文件与版本、镜号和结论，不新增字段或报告。文字通过不表示图像已生成、图像放行不表示用户已审；待检和制作方自述不能记作独立通过。

02定同场光色方案，04定现场光源、光区和变化，03给固有色与材质。06为同场、连续时段、同一光线状态维护共用look_setups，description自然记录光色、范围、02／04来源及固定基准镜号／正式图路径，shots[].look_ref引用它；lighting_setups沿04实际照明。每镜board_art_generation.prompt展开共用光色要求并补本镜塑形，references记录实际附入的固定基准image_ref与purpose；真实状态变化才切换对应记录，反打与切回复用原基准。首个基准完成前不填假图路径；旧数据缺记录仍兼容，本轮06制作补齐，05不负责填写。沿现有字段，不增加灯光参数表；同场颜色及美感并入已有图像检查，结构校验不能证明视觉一致。

06分三轮，使用同一镜号、画框与代表时刻：第一轮原生imagegen生成几何故事板，camera.placement记录06选定的摄影主轴、观看侧及机位，composition.frame_description记录取景、清晰关系及身体朝向、头部转向、可见脸部与实际目光目标的高低纵深，不新增方向字段；第二轮在裁图检查后再调用原生imagegen生成独立单张，落实身份造型、表演、场景道具与景深；第三轮以第二轮单张为输入，BANANA重新渲染真人质感与光影。三轮分别使用board_sheets[].generation、design_frames[].design_generation和board_art_generation记录真实工具及输入，不新增镜号、代表时刻或分析报告。旧数据兼容，不补造未发生的第二轮。专业责任见[共用约定](../../.agents/skills/novel-director-06/references/分镜设计职责与交接.md)。

| 字段 | 格式与用途 |
|---|---|
| board_sheets[页号].image_ref | 相对章节目录的第一轮几何故事板原页路径。 |
| width_px / height_px | 原页实际宽高。 |
| group_refs / frame_ids | 原页所含镜组和图号，须与每幅的引用一致。 |
| status / observation / generation | 页级镜头关系观察、采用的故事板提示词及实际参考；04图提供对应阶段的现场与全部实际轴线，同场采用的几何画格衔接状态及已定方向；摄影主轴、观看侧与画框由06选择。 |
| design_frames[].id | 稳定图号，示例为 S001-F01。 |
| sheet_ref / panel_id | 原页ID及格位ID。 |
| panel_region | [x,y,width,height]，以原图左上为原点的实际像素。 |
| design_frames[].design_ref / design_generation | 新三轮制作中，design_ref为第二轮原生独立单张的相对路径；design_generation含实际tool、prompt、references和实测resolution_px。references的几何参考以正式原页image_ref及panel_region登记，调用时实附有效裁图；角色与当场造型等参考另注用途。裁图不等于独立单张。旧稿design_ref的既有含义保留，不伪补生成记录。 |
| design_frames[].board_art | 第三轮BANANA重新渲染的最终采用净图，相对章节路径。原生独立单张已完成仍不代表最终图完成；07／08取board_art，历史已采用图保留真实来源。 |
| board_art_resolution_px | 最终采用图的实测 `[宽,高]`，与 project.resolution_px 的时间线规格分别记录。 |
| board_art_generation | 第三轮实际tool、prompt和references。tool如实记gemini-nano-banana-2.1，prompt保持第二轮单张的镜头、人物、状态、头身朝向与目光目标和清晰关系，增强真人质感与既定光影。references的首个几何参考必须为design_ref对应的独立单张路径，不能用故事板裁图代替；03资产、固定光色基准及相邻镜按用途另附。工具字段记录实际调用，不填计划回执。 |
| raw_panel_region | 可选，原页格框。采用视口须位于此框内部。 |
| status / observation | 实际生成状态和逐幅观察。 |
| annotations | 阅读器叠加的箭头与说明，具体结构见下节。 |

“分镜图册”按原页panel_region显示第一轮故事板；“正式分镜”读取board_art显示第三轮BANANA最终图。第二轮原生单张由design_ref引用，在镜头记录中保留可追溯路径。三轮保持相同画框、视点、景别、透视、人物位置与代表时刻；原生单张不能直接冒充第三轮最终图。阅读器既有SVG示例仍如实记录reader_demo_svg，不因方法修改伪称模型成图。

下列仅演示新流程的生成记录写法，不是既有示例图片的生成证明；生产时替换为实际输入与回执，沿用现有字段，无需升级schema_version：

```json
{
  "design_ref": "06_正式分镜/原生单镜/S001.png",
  "design_generation": {
    "tool": "imagegen",
    "prompt": "依参考图1生成独立单张，保持取景、视点、景别、透视与抓袖接触，两人的头身朝向仍沿门内通路，目光落在门口；按03当场造型和04姿态恢复人物，两人和门同时可辨，无宫格或文字。",
    "resolution_px": [2048, 1152],
    "references": [
      {"image_ref": "06_正式分镜/P01.png", "panel_region": [0, 0, 960, 540], "purpose": "参考图1：第一轮有效画格，裁出并检查后实附。"}
    ]
  },
  "board_art": "06_正式分镜/S001.jpg",
  "board_art_resolution_px": [2048, 1152],
  "board_art_generation": {
    "tool": "gemini-nano-banana-2.1",
    "prompt": "以参考图1的原生独立单张重新渲染，保持镜头、人物、头身朝向与看向门口的目光、抓袖接触和清晰关系；依既定冷白光色增强手背和袖褶塑形、自然肤质与暗部层次。",
    "references": [
      {"image_ref": "06_正式分镜/原生单镜/S001.png", "purpose": "参考图1：第二轮已生成并检查通过的独立单张，锁定镜头与内容。"}
    ]
  }
}
```

第二轮原生单张生成前，06独立检查者须实际检查裁好的本镜草稿及前后承接，具体范围按[06裁图检查规则](../../.agents/skills/novel-director-06/SKILL.md)。跨镜真实距离依据04地标与位置关系、05经过时间及已有动作判断，不能只比较两图中的大小和像素间隔。结构或关系错误先修几何草稿并同步采用原页、格位与引用，定向验收后实附修正版生成原生独立单张；第二轮单张再经独立新增偏差检查并向主Agent回报放行，才能送BANANA。旧错误草稿不得继续作为有效参考。

本次独立检查及修复确认的检查者、阶段、镜号范围、受检版本、有效来源和结论，使用已有design.review.board的scope/findings或原页observation简记，不增加字段。原页adopted不能代替裁图检查；草稿放行不代表原生单张已生成，原生单张放行不代表BANANA最终图完成或用户审定。尚未完成第三轮时board_art仍缺省、生成状态仍为required_not_generated，不将逐幅observation标成正式图adopted。按[06图像审核优先级](../../.agents/skills/novel-director-06/SKILL.md#图像审核优先级)，未解决P1／P2记needs_revision，缺必要依据记blocked；P3先放行，现有备注一次列可选调整，P4直接通过且不列问题。正式图已生成并经独立检查放行，仅有P3／P4时，board_art引用该图，observation.status可记adopted，不冒称用户已审，也不跨越委托停点。不新增优先级字段。分级是实际影响的判断，不是问题类型枚举；未列举的情况照样适用，不根据关键词或示例自动决定状态。这些记录不允许绕过实际看图，结构校验也不能验证画面正确。

observation.status 是该幅采用判断，优先于生成状态 status。采用状态不直接推导用户审定。

| 状态 | 页面行为 |
|---|---|
| adopted | 正式图已获独立检查放行并制作采用；包含已放行的P3／P4，P3可保留一次可选调整备注，不计入待修。 |
| needs_revision | 未解决P1／P2，或用户明确要求修改的项目；显示具体观察，原图仍可阅读。不能仅凭差异类型或是否命中示例决定状态。 |
| generated | 已生成、待采用。 |
| required_not_generated | 显示画面需求和时码。 |
| blocked | 显示受阻和已有说明。 |

06设计后、组页未生成时保留图号、代表帧、显示时段和画面决定，省略sheet_ref与格位；05不创建这些字段。组页完成补路径和格位，第二轮完成补design_ref与design_generation，第三轮完成补board_art及对应真实来源。前两轮完成时最终图状态仍为required_not_generated，不用页级采用或原生单张放行代替最终图完成。

      ]
    }

action 显示动作实线箭头，camera 显示机位虚线箭头，note 只显示短说明。points 可用多个点描述弯折路径，label_at 定位说明文字。原页和逐镜共用这组标注。06 阶段只填 action 及相关 note。07 将采用的 camera 箭头或固定 note 补进同一 annotations 列表，填写 author_step="07"。箭头是独立显示层，原图沿用。

## 声音与机位

需要跨切计时时，在design.sound_timeline[声音ID]提供上游source_ref和frame_range；已有kind、source、text等字段继续兼容，但不要求05另写。说话人、原词、声源变化、听点和表演读取02／04原件，不由05重新设计。

每镜 sound_cues 通过 cue_ref 引用声音，active_frame_range 为本镜内有效区间，用 continues_from_previous 和 continues_to_next 表达跨切延续。

空间图用scenes[场号].plan_ref引用04场地图，生产时沿用已交付图；旧数据缺省仍可读取。若一张SVG含多个镜组，再写plan_size=[宽,高]和plan_regions，例如{"G01":[0,0,900,620]}。坐标使用SVG自身viewBox单位，仅用于页面定位，不是现场尺寸。页面据本镜组取对应区域；省略分区时显示完整图。

## 07 运镜提示词

生产交接沿[主Agent的完成条件](../../AGENTS.md#如何推进)：完整范围的06完成后写07，07写齐并同步有效版本后写08。接口可保存逐步填写的数据，校验只证明结构与引用，不证明整个阶段已经完成；不另增阶段审批字段。

`motion_design` 保存运镜设计，逐镜以稳定镜号关联正式图。镜长、代表时刻和净图路径读取 `design.shots[镜号]`，与 05／06 共用同一来源。

```json
{
  "motion_design": {
    "source_design_revision": 1,
    "status": "working",
    "shots": {
      "S001": {
        "frame_id": "S001-F01",
        "intent": "让门外脚步打断观众对室内的观察。",
        "prompt": "3秒。起幅用远景同时看见左侧房门与右侧桌边的人，右窗光照着书页。前段保持参考图的空间关系，约1.46秒仍处于正式图构图。约2.5秒门外传来脚步，摄影机才朝门的方向横移，把门在画面中的分量加重，桌边的人仍在右侧。刚建立向门的动势便切到人物中景，脚步延续。"
      }
    },
    "review": {
      "scope": "本轮已完成镜头的纸面与图像推演",
      "findings": []
    }
  }
}
```

- `status` 使用 working、review_ready、approved，确认依据另记实际授权或用户反馈。
- `source_design_revision` 对应当前 `design_revision`。05／06 设计变更后，提示词需同步；只改提示词递增 `data_revision`。
- `shots[镜号]` 包含 `frame_id`、一句 `intent` 和可直接复制的完整 `prompt`。每镜对应唯一正式图。黑场沿剪辑时码处理。
- 整章交付覆盖全部摄影镜头；局部修订或独立片段用 `shot_ids` 列出本次范围，不据此缩小正在制作整章的完成范围。working可保存尚未写完的内容；review_ready／approved须覆盖有效委托范围并满足上述交接条件，不能把部分镜头写齐当成整章完成。
- 提示词中说明参考图落在开头、途中还是结尾，时间位置与既有代表帧一致。起幅、触发、运动过程、落幅和跨切承接由 07 设计。
- `review` 集中记录本轮纸面与图像推演范围、结论和待办。阅读器的“运镜提示词”页可逐镜阅读和复制；“状态”保留已有检查。
- `07_运镜提示词.md`从同一JSON导出，标题列镜号、镜长、正式图链接与代表时刻，高阶点带H编号；正文只写一段自然语言采用的运镜执行。intent保留在数据中，不另列意图和说明栏。检查记录留在review，修改后JSON与文稿同步。

## 08 分段声画提示词

08按04连续段落与银幕时长，读取02台词／OS与表演、03角色声线、04动作情绪与声音、05时序及07运镜，实际查看06最终单张并对照上游，补全、强化具体表演及同框活动，写成连续声画，交付章节内的`08_分段声画提示词.md`。每段列时间与镜号范围，附图清单登记“镜号／@图片N／board_art 原件”。可复制正文以“不要背景音乐，不要字幕”和段长开头；第一镜与每次切镜处就近写“镜头S001，时长2.5秒，分镜参考 @图片N”（切镜写“切到S002……”），镜长取05有效帧段及帧率，不能只列段总长；引用该镜的最终单张图后接具体表演与声画，写法见[08技能及完整示例](../../.agents/skills/novel-director-08/SKILL.md)。每镜单独提供图片附件，静态构图由图承载，一份提示词仍覆盖04的完整段落。

声线ID、样音版本和用户确认依据留在03及资产库，不进入08可复制正文，也不重复音色总述；只使用03确认后复制入项目资产库的角色样音，跨章直接复用，不重复询问；公共库路径仅供来源追溯，正式附件引用项目副本，实附后写简短音频与角色映射。候选或无确认依据的绑定交03提审，不能直接作为正式视频输入。当句的语气、情绪及呼吸表演仍保留。平台交付默认只配置视频节点，图像、样音和完整声画直接进入该节点，不要求额外的展示素材或文字节点。

该文稿作为阶段文件在“章节文稿与原件”中读取，不新增 JSON 字段，不改变 `schema_version: 4`，不替代 `motion_design`。版本与范围来源记在文稿中；09 汇报按实际完成情况引用。
